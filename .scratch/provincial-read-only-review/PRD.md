# Provincial Officer read-only review access

Status: ready-for-agent
Category: enhancement
Triaged: 2026-09-03

## Problem

A Provincial Officer can list the enrollments, factories and Score Reports of their province, but
cannot open a single Cover. The Evaluator can. The Officer therefore sees which factories are under
review and what they scored, but never the Answers, the evidence files or the standard certificates
behind those numbers.

The Officer is an oversight role. The Officer never records a Verdict Score and never finalizes a
Cover. This feature adds **read** access only.

## Decisions (settled during triage)

| # | Decision |
|---|----------|
| 1 | The Officer sees **all five** QuestionCategories — the same set an `ODPC` Evaluator sees. Provincial Officers have no evaluator level. |
| 2 | While a Cover is `in_review`, Verdict Scores are **hidden** from the Officer: no verdict choice, no description. |
| 3 | The Officer may open a Cover whose latest status is `in_review` or `finished`. An `in_progress` Cover is **not** readable. |
| 4 | Three endpoints ship: cover-review read, enrollment detail, factory detail. |
| 5 | Verdict Scores **become visible once the Cover is `finished`** — at that point they are the outcome, and the Grade derived from them is already on the Officer's Score Report endpoint. |
| 6 | Per-Answer `status` is **also hidden** while `in_review` (a bare `rejected` reveals the open review just as effectively as the verdict itself). |
| 7 | The new endpoints **enforce province scope** — an id outside the Officer's province is not readable. |
| 8 | The reviewer context in the review service gains a **three-way scope**: national, region, province. The province gate lives in the service, not in the routes. |
| 9 | The Officer's cover-review response **reuses the existing Evaluator response type**; hidden fields are null. No forked schema. |
| 10 | The redaction is applied **inside the review service**, driven by the scope discriminator. |
| 11 | The factory's standard certificates are **always visible**, at both statuses — they are factory-submitted, not Evaluator output. |

## Error semantics

Both gates return `404 { message: "cover not found" }` — out-of-province and `in_progress` alike.
A `403` would confirm the Cover exists and defeat the scope gate. This matches the existing
region-gated behavior.

## Out of scope

- Any write path for the Provincial Officer — no verdict save, no finalize, no edit.
- Changing what an Evaluator or a DOED admin sees. Their behavior must be byte-for-byte unchanged.
- Tightening the Evaluator enrollment/factory detail endpoints, which today perform no region check.
  Tracked separately in `.scratch/evaluator-detail-scope/`.
- File access control. `/file/presigned-url` is guarded by authentication only, with no ownership
  check, for every role today. That is pre-existing and unchanged here.
