# 01 — Three-way reviewer scope + province cover gate

Status: ready-for-agent
Category: enhancement

## Agent Brief

**Category:** enhancement
**Summary:** Widen the review service's reviewer context from `region: number | null` to an explicit three-way scope (national / region / province), and add a province-scoped Cover access gate.

**Current behavior:**
The evaluator-review service resolves a caller into a reviewer context carrying an evaluator level
and `region: number | null`, where `null` means "national" and bypasses the region gate. Cover access
is checked by a region-aware helper that either asserts the Cover's factory province sits in the
reviewer's health region, or asserts mere existence when the region is `null`. A DOED admin gets a
national context with level `ODPC`. A province is a third kind of scope that this shape cannot
express.

**Desired behavior:**
The reviewer context expresses scope as a discriminated union — national, region (with a region id),
and province (with a province id). Cover access dispatches on the discriminator: national asserts
existence, region asserts the Cover's factory province is in that health region, province asserts the
Cover's factory is in that province. A new resolver builds a province-scoped context from a Provincial
Officer account id, with level `ODPC` so that all five QuestionCategories are in scope.

Evaluator and DOED admin behavior must be unchanged — same responses, same status codes. This is a
type-level refactor plus one new scope arm.

**Key interfaces:**
- The reviewer-context type — replace `region: number | null` with a scope discriminator. Update the
  admin context factory and the evaluator resolver to produce the new shape.
- The cover-access helper — dispatch on the discriminator; add a province assertion that joins Cover
  to enrollment to factory and compares the factory's province id.
- A new resolver that turns a Provincial Officer account id into a province-scoped reviewer context,
  returning the existing `404 { message: "officer not found" }` status response when the caller is not
  a Provincial Officer. Reuse the existing Provincial Officer lookup rather than writing a new query.

**Acceptance criteria:**
- [ ] The reviewer context can express national, region and province scope, and the compiler rejects
      a context with no scope.
- [ ] A province-scoped reader can access a Cover whose factory is in that province.
- [ ] A province-scoped reader gets `404 { message: "cover not found" }` for a Cover in another
      province.
- [ ] The province resolver returns the existing not-found status response for a non-officer caller.
- [ ] The province-scoped context carries level `ODPC`, so category filtering includes all five
      QuestionCategories.
- [ ] Every existing evaluator-review test passes unchanged, including the admin/national path.
- [ ] `bun test` is green and `bun run check` reports no new findings.

**Out of scope:**
- Any route wiring — that is issue 02.
- The verdict redaction rule — that is issue 02, and lands on top of this scope.
- Changing what levels mean or adding a level column to Provincial Officers.
