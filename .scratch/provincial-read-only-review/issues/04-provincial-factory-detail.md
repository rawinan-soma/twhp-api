# 04 — Provincial factory detail endpoint

Status: ready-for-agent
Category: enhancement

## Agent Brief

**Category:** enhancement
**Summary:** Add a province-scoped factory detail read for the Provincial Officer.

**Current behavior:**
The Provincial Officer can list the factories of their province. There is no way to open one factory
record. The Evaluator has such an endpoint; it takes a factory id and returns the factory profile
joined with the province, district and subdistrict names — and it performs **no** scope check.

**Desired behavior:**
A Provincial Officer can read one factory by id under the provincial route group, guarded by the
officer guard, receiving the same record shape the Evaluator endpoint returns.

The endpoint **enforces province scope**: a factory outside the Officer's province returns
`404 { message: "factory not found" }`, identical to the response for a non-existent id.

**Key interfaces:**
- The factory service's by-id read — accept an optional province constraint, or add a province-scoped
  sibling. Prefer extending the existing read over duplicating its joins.
- A new route in the provincial group taking a factory id, resolving the caller's province from the
  existing Provincial Officer lookup.

**Acceptance criteria:**
- [ ] An Officer reads a factory in their province and receives the full profile including the
      location names.
- [ ] A factory in another province returns `404 { message: "factory not found" }`.
- [ ] A non-existent id returns the same `404`.
- [ ] The Evaluator's existing factory detail endpoint is unchanged.
- [ ] Integration tests cover the in-province read and the cross-province gate.
- [ ] `bun test` is green and `bun run check` reports no new findings.

**Out of scope:**
- Adding a scope check to the Evaluator endpoint. Tracked in `.scratch/evaluator-detail-scope/`.
- Any mutation of the factory record, including validation flags.
