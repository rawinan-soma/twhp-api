# 02 — Provincial cover-review read endpoint

Status: ready-for-agent
Category: enhancement
Depends on: 01

## Agent Brief

**Category:** enhancement
**Summary:** Give the Provincial Officer a read-only cover-review endpoint, scoped to their province, with Verdict Scores hidden while the Cover is `in_review`.

**Current behavior:**
Only an Evaluator (region-scoped) and a DOED admin (national) can read the Answers of a single Cover.
The read returns, per Answer, the factory's selected choice, the evidence filenames, the per-Answer
status and the latest Verdict Score with its description — plus the factory's claimed and uploaded
standard certificates. A Provincial Officer has no equivalent, so they can see a Score Report for a
Cover but none of the Answers behind it.

**Desired behavior:**
A Provincial Officer can read the Answers of a Cover in their own province under the provincial route
group, guarded by the officer guard. The reader is province-scoped (issue 01).

Two rules apply to a province-scoped reader and to no other reader:

1. **Status gate.** The Cover's latest status must be `in_review` or `finished`. A Cover whose latest
   status is `in_progress` is not readable and returns `404 { message: "cover not found" }`, the same
   response as an out-of-province Cover — a distinct code would confirm the Cover exists. Derive the
   latest status with the existing cover-status helper rather than a new query.
2. **Verdict redaction.** While the Cover is `in_review`, every Answer's latest verdict choice and
   description are `null`, and the per-Answer status reads `in_review` regardless of what the
   Evaluator has recorded. Once the Cover is `finished`, the Officer sees the same verdict values an
   Evaluator sees.

The factory's standard certificates are returned at both statuses, unredacted.

The redaction is applied **inside the review service**, selected by the scope discriminator — not by
the route stripping fields from a response. A region-scoped or national reader is never redacted.

The response reuses the existing cover-review response type. The verdict fields are already nullable,
so no new schema is introduced; the OpenAPI description records that the fields are withheld while
the Cover is under review.

**Key interfaces:**
- The review service's Answer-read function — apply the status gate and the redaction for
  province-scoped readers, returning the same response type as today.
- A new route in the provincial group taking a cover id, using the officer guard and the province
  resolver from issue 01.

**Acceptance criteria:**
- [ ] An Officer reading a Cover in their province with status `in_review` receives all five
      QuestionCategories of Answers, with the factory's selected choice and evidence filenames.
- [ ] On that `in_review` Cover, every Answer has a null verdict choice, a null description, and a
      status of `in_review` — including Answers the Evaluator has already recorded a verdict on.
- [ ] The standard certificates are present on that `in_review` Cover.
- [ ] Once the Cover is `finished`, the same Officer sees the verdict choice, description and status
      exactly as an Evaluator does.
- [ ] A Cover whose latest status is `in_progress` returns `404 { message: "cover not found" }`.
- [ ] A Cover in another province returns `404 { message: "cover not found" }`.
- [ ] An Evaluator or DOED admin reading any Cover sees an unchanged response — no redaction, no
      status gate.
- [ ] A non-officer role calling the endpoint is rejected by the guard.
- [ ] Integration tests cover the `in_review` redaction, the `finished` reveal, the `in_progress`
      gate and the cross-province gate.
- [ ] `bun test` is green and `bun run check` reports no new findings.

**Out of scope:**
- Any write path. The Officer must not reach verdict save or finalize.
- Changing the Evaluator's ability to open an `in_progress` Cover. That behavior stays as it is.
- Presigned-URL access control for the evidence files.
