# 03 — Provincial enrollment detail endpoint

Status: ready-for-agent
Category: enhancement

## Agent Brief

**Category:** enhancement
**Summary:** Add a province-scoped enrollment detail read for the Provincial Officer.

**Current behavior:**
The Provincial Officer can list the enrollments of their province, paginated and filterable by cover
status. There is no way to open one enrollment and see the full record. The Evaluator has such an
endpoint; it takes an enrollment id and returns the enrollment columns joined with the province,
district and subdistrict names — and it performs **no** scope check at all.

**Desired behavior:**
A Provincial Officer can read one enrollment by id under the provincial route group, guarded by the
officer guard, receiving the same record shape the Evaluator endpoint returns.

Unlike the Evaluator endpoint, this one **enforces province scope**: an enrollment whose factory is
not in the Officer's province returns `404 { message: "enroll not found" }` — the same response as a
non-existent id, so the endpoint never confirms that an out-of-province enrollment exists.

**Key interfaces:**
- The enrollment service's by-id read — either accept an optional province constraint or gain a
  province-scoped sibling. Prefer extending the existing read over duplicating its joins.
- A new route in the provincial group taking an enrollment id, resolving the caller's province from
  the existing Provincial Officer lookup.

**Acceptance criteria:**
- [ ] An Officer reads an enrollment whose factory is in their province and receives the full record
      including the province, district and subdistrict names.
- [ ] An enrollment in another province returns `404 { message: "enroll not found" }`.
- [ ] A non-existent id returns the same `404`.
- [ ] The Evaluator's existing enrollment detail endpoint is unchanged.
- [ ] Integration tests cover the in-province read and the cross-province gate.
- [ ] `bun test` is green and `bun run check` reports no new findings.

**Out of scope:**
- Adding a scope check to the Evaluator endpoint. Tracked in `.scratch/evaluator-detail-scope/`.
- Any mutation of the enrollment.
