# 05 — API tracing: own request-span hook, pg spans, scrubbing, `X-Request-Id`

Status: ready-for-agent
Category: enhancement
Blocked by: 01, 02 (logger `mixin`), 04 (acceptance checks traces in Tempo)
Model: Opus 5.5, medium effort (hand-written span hook, AsyncLocalStorage and instrumentation-pg under Bun)

## Agent Brief

**Category:** enhancement
**Summary:** Trace every API request with a hand-written Elysia hook, add PostgreSQL and hand-written dependency spans, put `trace_id` in logs, and return it as `X-Request-Id`.

**Current behavior:**
No tracing. Logs have no request correlation. Responses carry no request ID.

**Desired behavior:**
- **Telemetry bootstrap**, loaded before any app module via Bun `preload` for the API process:
  - registers a `NodeTracerProvider` with resource attributes `service.name=twhp-api` and
    `deployment.environment=$DEPLOYMENT_ENV`;
  - uses an `AsyncLocalStorageContextManager` and a global W3C trace-context propagator (issue 06
    needs it);
  - uses a `BatchSpanProcessor` with an OTLP/proto exporter to `OTEL_EXPORTER_OTLP_ENDPOINT` **only
    when that variable is set**;
  - registers `@opentelemetry/instrumentation-pg`, with statement parameters **not** recorded.

  When the endpoint is unset, spans are still created, so trace IDs, `X-Request-Id` and log
  correlation still work, but nothing is exported. An unreachable collector must never fail or slow a
  request.
- **Request-span hook, ours, not `@elysiajs/opentelemetry`** (ADR-0014): one SERVER span per request.
  - Name: `<METHOD> <route template>`.
  - Attributes: `http.request.method`, `http.route`, `url.path` without query string,
    `http.response.status_code`, and `enduser.id` = `userId` when authenticated.
  - Status: error on 5xx, and the exception recorded for unexpected errors.
  - **Allow-list only:** no request or response headers, cookies, query string, body, client IP or
    user-agent are ever set as attributes.
  - Inbound `traceparent`/`tracestate` headers are **ignored**; every request starts a new trace.
  - `/health*` is not traced.
  - Every handler, service call and DB query runs inside the request span's context.
- **Hand-written CLIENT spans** for calls Bun cannot auto-instrument:
  - the MinIO helpers (`uploadFile`, `deleteFile`, `getPresignedUrl`): operation name and bucket
    only; never object names, presigned URLs or signatures;
  - `emailQueue.add` (BullMQ adds its own spans in issue 06; only add one here if BullMQ's is absent).
- **`X-Request-Id` response header** equal to the trace ID (32 hex chars) on every response, including
  400/401/404/500 responses.
- **Logs:** the logger `mixin` from issue 02 returns `{ trace_id, span_id }` from the active span, so
  every request line and every `ctx.log`/`onError` line carries them.
- **Config:** `OTEL_EXPORTER_OTLP_ENDPOINT` (optional, URL) and `DEPLOYMENT_ENV` (optional, default
  `development`) are added to `src/config.ts` with the existing optional-env helpers.

**Key interfaces:**
- A telemetry bootstrap module (tracer provider setup) and a `bunfig.toml` preload entry for the
  API run.
- An Elysia plugin exposing the request span, applied before autoload.
- `utilities()` MinIO helpers wrapped in spans.
- `env.OTEL_EXPORTER_OTLP_ENDPOINT`, `env.DEPLOYMENT_ENV`.

**Acceptance criteria:**
- [ ] A test using an in-memory span exporter shows that `GET /twhp/api/<route>/:id` produces one
      SERVER span named with the route template, with a child `pg` span when the route hits the DB.
- [ ] A test with `Cookie: Authentication=abc; Refresh=def`, `Authorization: Bearer xyz`,
      `?fileName=secret` and a user-agent finds none of `abc`, `def`, `xyz`, `secret` or the
      user-agent in any attribute of any exported span.
- [ ] A test sending `traceparent: 00-<known trace id>-...` gets a response whose `X-Request-Id`
      differs from the sent trace ID.
- [ ] Every response (200, 400, 401, 404, 500) has a 32-hex `X-Request-Id`, and the request's log line
      has the same `trace_id`.
- [ ] With `OTEL_EXPORTER_OTLP_ENDPOINT` unset, the isolated suite passes and no network export is
      attempted.
- [ ] With the endpoint pointing at a closed port, request latency in a smoke test is not noticeably
      affected. Export is async and failures are swallowed or logged once.
- [ ] With the `observability` profile up, a request's trace is visible in Grafana → Tempo, and
      clicking through to Loki shows its log lines.
- [ ] `@elysiajs/opentelemetry` is not in `package.json`.
- [ ] The isolated test suite passes, and `biome check src` reports no new findings.

**Out of scope:**
- Worker tracing and queue propagation (issue 06).
- Metrics (issue 07).
- Frontend display of the request ID.
- Sampling. It is 100% by decision.
