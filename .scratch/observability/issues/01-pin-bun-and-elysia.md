# 01 — Pin Bun and Elysia versions

Status: closed
Category: enhancement

## Agent Brief

**Category:** enhancement
**Summary:** Make the Bun runtime and the Elysia version exact and identical across developer machines, CI and Docker images.

**Current behavior:**
Nothing pins Bun: there is no `.bun-version`, no `engines` field and no `packageManager` field, and
the Dockerfile uses the floating tags `oven/bun:1` and `oven/bun:1-slim`. A developer laptop ran
1.3.6 while the images resolved to 1.4.2. `elysia` is declared as `"latest"`; the lockfile resolves
1.4.28. `bun-types` is also `"latest"`. OpenTelemetry behavior differs between Bun minors, so an
unpinned rebuild can silently change what gets traced.

**Desired behavior:**
- Both Dockerfile stages use an exact Bun tag, `1.4.2` and `1.4.2-slim`, unless a newer patch is
  current when this is picked up. Then use it and say so.
- A `.bun-version` file at the repo root names the same version.
- `package.json` declares the same version in an `engines.bun` field.
- `elysia` and `bun-types` are pinned to the exact versions already resolved in `bun.lock`. No
  dependency is upgraded as a side effect.
- Developer docs (`docs/development.md`, and `README.md` if it names a Bun version) say which
  version to install and point at `.bun-version`.

**Key interfaces:**
- Dockerfile `FROM` lines, both stages.
- `package.json` `engines` and the `elysia`/`bun-types` specifiers.
- `bun.lock` must not change resolved versions beyond what the specifier change forces.

**Acceptance criteria:**
- [ ] `grep -n "FROM oven/bun" Dockerfile` shows exact versions only, with no floating `:1`.
- [ ] `.bun-version` exists, and its version matches the Dockerfile tag and `engines.bun`.
- [ ] `package.json` has no `"latest"` specifiers.
- [ ] `bun install --frozen-lockfile` succeeds.
- [ ] `docker build --target build .` succeeds and `bun --version` inside it prints the pinned version.
- [ ] The isolated test suite listed in `CLAUDE.md` passes on the pinned version.
- [ ] `bun ./node_modules/.bin/biome check src` reports no new findings.

**Out of scope:**
- Upgrading Elysia, BullMQ or any other dependency.
- Any telemetry code.
