# 03 — Split health into live and ready

Status: ready-for-agent
Category: enhancement

## Agent Brief

**Category:** enhancement
**Summary:** Add `/health/live` and a dependency-checking `/health/ready`, keeping `/health` as a live alias.

**Current behavior:**
`GET /twhp/api/health` returns the constant string `"Ready to work!!"` whenever the process is up.
Docker Compose healthchecks for `api-dev` and `api` call it. It says nothing about PostgreSQL, Redis
or MinIO.

**Desired behavior:**
- `GET /twhp/api/health/live` returns 200 with no dependency checks. It is as cheap as today.
- `GET /twhp/api/health/ready` checks, in parallel and each with a short timeout (≈1 s):
  - PostgreSQL: `select 1`;
  - Redis: `PING` on the connection BullMQ already uses, or an equivalent existing client;
  - MinIO: a bucket-exists call on the configured bucket.

  It returns 200 `{ status: "ready", checks: { postgres: "up", redis: "up", minio: "up" } }` when all
  pass. Otherwise it returns 503 with the same shape, the failing ones marked `"down"`. It returns no
  error messages, hostnames or credentials.
- `GET /twhp/api/health` keeps working, returns 200 with the unchanged `"Ready to work!!"` body, and
  behaves like live.
- All three stay excluded from request logs.
- Compose healthchecks keep using a liveness path, so a dependency blip does not restart the API.
- The readiness check is exposed as a reusable function, because issue 07 publishes it as a metric.
- OpenAPI detail for the new routes, and `docs/` updated where `/health` is described
  (`docs/deployment.md`, `docs/troubleshooting.md`).

**Key interfaces:**
- A health service with `checkReadiness(): Promise<{ postgres, redis, minio }>` in the factory
  pattern (`createHealthService(db, ...)`), so tests can inject failing clients.
- Response schemas in `src/schema/`.

**Acceptance criteria:**
- [ ] A unit test with all dependencies up gives 200 and all `"up"`.
- [ ] A unit test with an injected failing Redis gives 503 and `redis: "down"`, with the others
      `"up"`.
- [ ] A unit test with an injected hanging dependency returns within about 1.5 s.
- [ ] `/health` returns 200 `"Ready to work!!"`, unchanged.
- [ ] Health routes produce no request log lines.
- [ ] The isolated test suite passes, and `biome check src` reports no new findings.

**Out of scope:**
- SMTP and worker checks. The worker's liveness comes from metrics in issue 07.
- Exposing health through nginx differently from today.
- Graceful shutdown.
