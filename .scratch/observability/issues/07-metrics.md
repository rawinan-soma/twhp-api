# 07 — Metrics: `prom-client` on an internal port for API and worker

Status: ready-for-agent
Category: enhancement

## Agent Brief

**Category:** enhancement
**Summary:** Expose Prometheus metrics from the API and the worker on an internal-only port, covering HTTP traffic, dependency health and the email queue.

**Current behavior:**
No metrics endpoint exists.

**Desired behavior:**
- Each process (API, worker) serves `GET /metrics` on `METRICS_PORT` (default `9464`), using a
  **separate `Bun.serve` listener**. It is not a route under `/twhp/api`, so nginx can never proxy
  it, and it is not published by Compose.
- **Common:** `prom-client` default metrics with the label `service` (`twhp-api` / `twhp-worker`).
- **API metrics:**
  - `http_server_request_duration_seconds` histogram, labels `method`, `route` (the route
    **template**, never the raw path) and `status_class` (`2xx`…`5xx`). Buckets cover 5 ms – 10 s.
    `/health*` excluded. Unmatched routes use `route="unmatched"` so 404 scans can't explode
    cardinality.
  - `twhp_dependency_up` gauge, label `dependency` (`postgres`, `redis`, `minio`), 1/0. Computed at
    scrape time from issue 03's readiness check, cached ≤ 10 s.
- **Worker metrics:**
  - `twhp_email_jobs_total` counter, labels `job_name`, `outcome` (`completed` / `failed`), fed from
    the worker's `completed`/`failed` events.
  - `twhp_email_queue_jobs` gauge, label `state` (`waiting`, `active`, `delayed`, `failed`), from
    `getJobCounts()` at scrape time.
  - `twhp_email_queue_oldest_waiting_seconds` gauge: the age of the oldest waiting job, 0 when
    none.
- No label ever carries a user ID, factory ID, email or any other unbounded or personal value.
- `METRICS_PORT` is added to `src/config.ts` as an optional number.

**Key interfaces:**
- A shared metrics module (registry, default metrics, a helper to start the metrics listener).
- An Elysia hook recording request duration by route template. It can share the plumbing of issue
  05's request hook.
- The worker event wiring for the counter.

**Acceptance criteria:**
- [ ] `curl http://localhost:9464/metrics` inside the API container lists
      `http_server_request_duration_seconds_bucket`, `twhp_dependency_up` and `process_cpu_seconds_total`.
- [ ] After `GET /twhp/api/<route>/123` and `/456`, exactly one `route` label value exists for that
      route (the template).
- [ ] A test with an injected down Redis gives `twhp_dependency_up{dependency="redis"} 0`.
- [ ] The worker's `/metrics` shows `twhp_email_jobs_total{outcome="failed"}` increment after a
      forced SMTP failure in a test.
- [ ] `docker compose config` shows no published `9464`, and nginx has no `/metrics` route.
- [ ] With the `observability` profile up, Prometheus shows the API and worker targets `up`.
- [ ] The isolated test suite passes, and `biome check src` reports no new findings.

**Out of scope:**
- Dashboards and alert rules (issue 08).
- Business metrics (submissions, grades).
- `postgres_exporter` / `redis_exporter`.
