## Agent Brief

**Category:** bug
**Summary:** Narrow the `gold` special gate from `special` 1 and 3 to `special == 1` only, make `consec-gold` gate on `special` 1 and 2, and make the FY2569 backfill SQL grade with the same rule as the code.

**Current behavior:**

The maintainer's rule is: **`gold` requires the literal choice `"3"` on every
Question where `special == 1`**. No other `special` value gates `gold`.

Three places each implement a different rule, and none of them is the
maintainer's:

| Where | `gold` gate: Answers that must be `"3"` |
| --- | --- |
| Maintainer's rule | `special == 1` (3 Questions today) |
| `computeGrade` (shipped in #14, ticket 02) | `special` 1 **and** 3 (6 Questions) |
| `backfill-fy2569.sql` (ticket 04) | `special > 0` — the pre-#14 rule (all 11) |

Ticket 02 read `CONTEXT.md` ("`special` is `1` or `3`") as the intended rule
and settled the BR-23 / TD-06 conflict in its favour. The document itself was
wrong, so the drift went into `CONTEXT.md`, `docs/business-rules.md` BR-23,
ADR-0014, the consecutive-gold PRD, `CLAUDE.md`'s "Grade ladder" section, and
the other handover docs that restate the gate.

Verified on `dev` at `b81c9b4`: `computeGrade` gates `gold` on
`specialsAllFullScore(answers, [1, 3])`, and the `score.test.ts` case
*"a special == 3 Answer below 3 cannot reach gold"* asserts the drifted rule.
The SQL gates on `bool_and(selected_choice = '3') FILTER (WHERE q.special > 0)`
in both its preview and its insert.

**Desired behavior:**

The Grade ladder, top-down, first match wins:

| Grade | Rule |
| --- | --- |
| `consec-gold` | the `gold` gate **and** every `special == 2` Answer is `"3"` **and** a gold-tier award (`gold` or `consec-gold`) in the Cover's fiscal year − 3 |
| `gold` | every category > 80%, total >= 90%, every `special == 1` Answer is `"3"` |
| `silver` | every category > 60%, total >= 80% (unchanged) |
| `certificate` | total >= 60% (unchanged) |
| `joined` | otherwise (unchanged) |

So `consec-gold`'s special set is `{1, 2}`. **`special == 3` gates no tier.**
It keeps its unrelated meaning (one evidence file per choice).

`n/a` still never satisfies a special gate. A Cover with no gating Answers is
still graded on its percentages alone.

**The FY2569 backfill uses this same rule** (maintainer's decision, 2026-09-21).

saw. `backfill-fy2569.sql` must:

## Notes

- **Why the maintainer, not the doc, is authoritative.** `CONTEXT.md` said
  "`special` 1 or 3" before ticket 02, and ticket 02 treated that as the
