### Design Decision Confirmed in Implementation

`fiscalYear` in responses derives from the **resolved window**, not per row. Implemented as a single
`stampFiscalYear` / `.map()` at each list boundary using the year the resolver returned, so the
displayed year cannot disagree with the filter that selected the row.

The resolver was extended to return `fiscalYear` alongside the two boundaries. This is **additive** —
all 14 existing call sites destructure only `fiscalYearStart` and `fiscalYearEnd` and are unaffected.
It avoids a second clock read and a second derivation, which is exactly the divergence this intent
exists to reduce. Recorded as a deviation from run 001's "return shape unchanged" wording, which was
aimed at churn at call sites; zero churn still holds.
