## Caveat carried into `fiscal-year-boundary-tests`

The suite has **not** been run under multiple host timezones. `factory-pagination.integration.test.ts:159-160`
builds `new Date(fiscalYearStart.getFullYear() - 1, 9, 1)` — host-local construction — so it is
already timezone-fragile. This baseline reflects the test host's timezone only.

Establishing TZ-independence is scoped to work item `fiscal-year-boundary-tests`, not assumed here.
